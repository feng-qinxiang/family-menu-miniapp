# 会员归属家庭而非用户

> **已被 ADR-0005 取代**：模型在盘问中翻转为「会员绑定购买者用户 + 可选共享给当前家庭」。本 ADR 保留以记录决策演进。

接入真实微信支付前，需确定 VIP 会员的归属主体。现状 `vip_status` / `plan_name` 挂在 `user_account` 上（按用户），但产品名为「家庭版」、套餐名为「家庭年卡」、云同步等权益本质是家庭维度。

**决策**：会员归属 `family`。任一家庭成员购买即升级整个家庭；某个用户是否为 VIP，通过其当前所属家庭的会员状态推导，不再直接读 `user_account.vip_status`。

**理由**：贴合「家庭版」产品前提，避免「一人付费、其他成员仍看广告」的客诉；真金白银交易后归属难以回头，按家庭出售更站得住脚。

**影响**：VIP 状态从 `user_account` 迁出到家庭维度（`family` 表或新建 `family_membership` 表）；`vipStatus(userId)` 改为「先查用户所属家庭，再查家庭会员」。
