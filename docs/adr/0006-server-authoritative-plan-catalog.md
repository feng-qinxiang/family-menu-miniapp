# 套餐目录后端权威，金额时长不可由前端决定

接入支付（含模拟期）需定义「卖什么、卖多少钱」，并堵住定价被前端篡改的洞。现状 activateVip 直接接收前端传来的 planName 字符串、金额未参与，存在「0.01 元买年卡」式风险。

**决策**：
1. 套餐目录由后端权威定义，以 `plan_code` 标识（如 monthly = 30 天、annual = 365 天）。
2. 前端下单只传 plan_code；金额与时长一律由后端按 code 查出，前端传来的任何价格/时长忽略。
3. 订单金额以 `amount_fen`（分，整数）存储，杜绝浮点误差。
4. MVP 阶段套餐目录为后端硬编码常量（仅两三档），暂不建配置表；待需要促销/多档位再上表。

**理由**：金额与时长由前端决定是支付类功能的典型越权漏洞，模拟期也必须堵住；改价是低频高危操作，不该交给运营随意改，故 MVP 硬编码而非配置表，避免过度设计。

**影响**：下单接口入参由 planName 改为 plan_code；新增后端套餐常量定义；订单与会员的金额、时长字段取自后端查表结果。
