# 支付与登录接口契约（交付版 v1）

> Agent-1 制定，前后端 agent 必须严格按此实现，保证对接不错位。
> 口径：A+B —— 代码做到真实可用，缺商户/短信凭据时**优雅降级 + 明确标注待配置**，绝不静默假成功。

## 一、微信支付（JSAPI / 微信支付 v3）

### 后端接口

| Method+Path | 鉴权 | 请求 | 响应 |
|---|---|---|---|
| `POST /api/payment/orders` | A | `{planId}` | `{orderId, outTradeNo, amountFen, planId, planName}` |
| `POST /api/payment/orders/{orderId}/prepay` | A | `{}` | 见下 PrepayResponse |
| `POST /api/payment/notify` | Public(微信回调) | 微信加密报文 | `{code:"SUCCESS"}`/`{code:"FAIL"}` |
| `POST /api/payment/mock-pay` | A | `{orderId}` | `PayResult`（**仅 dev/未配置商户时可用**） |
| `GET /api/payment/orders` | A | - | `List<OrderView>`（真实订单流水） |

### PrepayResponse 结构

```jsonc
{
  "mockMode": false,            // true=商户未配置，前端降级走 mock-pay
  "appId": "wx...",
  "timeStamp": "1700000000",
  "nonceStr": "abc...",
  "package": "prepay_id=wx...",
  "signType": "RSA",
  "paySign": "..."             // 微信支付二次签名；mockMode=true 时为空
}
```

### 配置（application.yml，缺失则 mockMode=true 并告警，绝不报错崩溃）

```yaml
wechat:
  pay:
    mch-id: ${WECHAT_MCH_ID:}                 # 商户号
    api-v3-key: ${WECHAT_PAY_API_V3_KEY:}     # APIv3 密钥
    cert-serial-no: ${WECHAT_PAY_CERT_SERIAL:} # 商户证书序列号
    private-key-path: ${WECHAT_PAY_KEY_PATH:}  # 商户私钥 PEM 路径
    notify-url: ${WECHAT_PAY_NOTIFY_URL:}      # 回调地址（公网）
```

### 前端 onPay 流程（pages/payment/checkout）

1. `api.createPaymentOrder({planId})` → orderId
2. `api.prepayOrder(orderId)` → PrepayResponse
3. 若 `mockMode===false`：调 `wx.requestPayment({timeStamp,nonceStr,package,signType,paySign,success/fail})`，success 后跳 `payment/success`（订单状态由后端 notify 置 PAID）
4. 若 `mockMode===true`：`wx.showModal` 明确提示「支付通道未配置，当前为本地联调开通」→ 用户确认后 `api.mockPayOrder(orderId)` → 跳成功页。**不得伪装成真实支付成功。**

## 二、微信登录（已真实，仅需配置）

- `AuthService` 已真实调用 `jscode2session`；`WECHAT_APP_ID/SECRET` 留空时 `/api/auth/login` 对真实 code 返回 503 并引导手机号/游客。前端登录页需正确处理该降级。

## 三、短信 OTP（生产网关接入点）

- 后端在 `requestPhoneOtp` 生成随机码后，调用 `SmsGateway` SPI 发送；未配置网关时：dev 模式回显 `devCode`，生产模式仅落库并日志告警「短信网关未配置」。SPI 接口预留，便于后续接阿里云/腾讯云短信。

## 四、忌口字段

- `family_member` 增加 `avoid_tags_json`（JSON 数组），创建/编辑成员可写，菜单推荐与今日菜单过滤需读取。

## 五、/api/vip/activate 旁路

- 该端点为遗留直接开通通道，与「开通只能由订单 PAID 触发」冲突。交付处理：保留但限制为 dev/内部用途，或前端不再调用、统一走订单流程。前端 VIP 升级页改为走 `payment/checkout` 订单流程。
