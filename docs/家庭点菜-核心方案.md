# 家庭点菜 · 核心方案（钉死版）

> 本文件是产品方向的唯一真源（single source of truth）。`产品方案.md` / `MVP功能清单.md` 中
> 与本文件冲突的部分以本文件为准。后续任何页面/接口/数据模型变更必须先回这里对齐。

## 0. 一句话定位

**一家人围绕一顿饭、一天饭、一周饭，一起决定"吃什么"，然后买、做、记。**

不是菜谱站，不是外卖系统。主战场是「点菜」（决策），其次是「菜单」（执行）。

---

## 1. 核心决策汇总

| 项 | 决定 |
|---|---|
| 登录 | 6 个页面全保留（login / login-phone / verify-otp / register / reset-password / wechat-auth），UI 风格统一 |
| 支付 | 代码与路由全部保留，**功能暂缓开发**，等到 VIP 上线节点再续 |
| 家庭模型 | **默认家庭**：登录即自动创建 1 人家庭，可邀请家人升级为多人家庭 |
| Tab 数 | **4 个**：点菜 / 菜单 / 菜谱 / 我的 |
| 主战场 | Tab1「点菜」 |
| 多人输入默认 | **许愿池**（投票、自由叠加为附加动作） |
| 餐次粒度 | 早 / 午 / 晚 三餐 + 本周视图（7×3 槽） |
| 餐次默认 | 进入点菜默认锚定**晚餐**；管理员可在家庭设置里调整默认/隐藏某餐 |
| 角色 | 管理员 / 做饭人 / 成员 三级 |

## 2. Tab 结构

```
Tab1 [点菜]   pages/home/index          ★主战场（决策）
Tab2 [菜单]   pages/menu/index           执行视图（已确认的菜）
Tab3 [菜谱]   pages/recipes/index        弹药库（家庭菜谱 + 收藏 + 社区 + 导入）
Tab4 [我的]   pages/me/index             家庭管理 + 偏好 + 设置 + VIP 等
```

**降为子页、不进 Tab 的页面**：

- `pages/weekly-menu/`     → 并入 menu 的「本周」segment
- `pages/cook-mode/`       → 菜单卡片「开始做饭」打开的浮层/子页
- `pages/cook-log/`        → 做饭完成弹窗后写入，详情挂菜谱"我做过 N 次"
- `pages/shopping/`        → 菜单底部「一键生成购物清单」入口
- `pages/pantry/`          → shopping 顶 tab「家里已有」
- `pages/me/preference-profile/` → 我的「偏好画像」入口，作为筛选条件真源
- `pages/community/`、`pages/import/` → 菜谱 Tab 内的 segment

登录全套、家庭 create/join/members/invite、VIP、支付、法务、launch 均不进 Tab。

## 3. Tab1「点菜」页结构

```
┌─ 顶部餐次选择器 ──────────────────────────────┐
│  [今日·早] [今日·午] [今日·晚★]  [本周 ▾]    │
└───────────────────────────────────────────────┘
┌─ 本餐许愿池 ─────────────────────────────────┐
│  · 妈妈想吃：番茄炒蛋                         │
│  · 我加的：红烧肉                             │
│  · 自由叠加 [+]                              │
└───────────────────────────────────────────────┘
┌─ 候选菜来源 ─────────────────────────────────┐
│ [我做过的] [社区] [随机] [按食材] [发起投票] │
└───────────────────────────────────────────────┘
┌─ 底部行动条 ─────────────────────────────────┐
│  [做饭人确认 →]  (按角色高亮/置灰)            │
└───────────────────────────────────────────────┘
```

确认后：许愿池清空 → 内容沉到 Tab2「菜单」对应餐次槽。

## 4. 多人输入：三态共存，默认许愿池

| 动作 | 入口 | 谁能做 |
|---|---|---|
| 许愿（默认） | 许愿池 `[+]` | 所有家庭成员 |
| 自由叠加 | 许愿池条目"加入菜单"按钮 | 管理员 / 做饭人 |
| 投票 | "发起投票"按钮 | 所有人发起，所有人投 |

投票发起后许愿池切换为投票 UI；投票截止或人工结束后回到许愿池态。

---

## 5. 餐次模型

- 最小颗粒：`meal = (date, slot)`，slot ∈ {breakfast, lunch, dinner}
- 「今日」= 3 个 meal；「本周」= 7×3 = 21 个 meal
- 进入「点菜」默认锚定 `(today, dinner)`
- 家庭设置可配置：
  - 默认餐次（dinner / lunch / breakfast）
  - 是否隐藏早餐（不少家庭早餐固定，UI 上隐藏对应槽位）

---

## 6. 权限矩阵

| 动作 | 管理员 | 做饭人 | 成员 |
|---|---|---|---|
| 许愿 | ✅ | ✅ | ✅ |
| 自由叠加进菜单 | ✅ | ✅ | ❌（只能许愿） |
| 确认 / 锁定菜单 | ✅ | ✅ | ❌ |
| 发起投票 | ✅ | ✅ | ✅ |
| 投票 | ✅ | ✅ | ✅ |
| 开始做饭 / cook-log | ✅ | ✅ | ❌ |
| 改家庭名 / 踢人 / 转让管理员 | ✅ | ❌ | ❌ |
| 任命做饭人 | ✅ | ❌ | ❌ |
| 改默认餐次 / 隐藏早餐 | ✅ | ❌ | ❌ |

- 创建家庭者自动成为管理员，一个家庭至少 1 个管理员。
- 一个家庭可有多个做饭人。
- 默认家庭（仅创建者一人）时，本人即管理员 + 做饭人 + 成员。
