# 家庭点菜小程序 · 页面需求说明书

> 版本：v1.0　编写日期：2026-09-11　对应代码：`miniapp/`（提交 e23c491）
> 说明：本文按"页面类型 → 功能模块 → 结构与跳转 → 展示数据 → 作用与场景"逐页说明，
> 所有路径、字段与开关均取自当前代码，非规划稿。

---

## 0. 全局约定

### 0.1 包体与页面规模

| 包 | 页面数 | 内容 |
|---|---|---|
| 主包 `pages/` | 29 | 5 个 tab 页 + 核心业务二级页（菜谱/菜单/采购/烹饪/社区/家庭/我的/登录/法律） |
| 分包 `pkg-extra/` | 8 | 低频与"资质相关"页面：帖子详情、社区审核、收藏、会员、支付收银台/成功页 |
| **合计** | **37** | 主包直出，分包按需加载，目的是压住主包体积（上线要求 < 2MB） |

**分包划分依据**：帖子详情、收藏、会员与支付都属于"不是每次打开都要用"的页面，放分包可让主包只保留主链路。

### 0.2 导航骨架

- **tabBar 自定义**（`custom: true`），5 项：**今日 → 菜谱 → 社区 → 冰箱 → 我的**，顺序与路径由 `utils/tabs.js` 的 `ALL_TABS` 唯一声明。
- `app.json` 的 `tabBar.list` 必须静态声明（微信限制），而 `visibleTabs()` 按开关决定**渲染几项**——社区 tab 受 `features.COMMUNITY` 控制，关闭时只是不渲染，声明仍在。两者一致性由 `test/static-check.js` 自动校验。
- **跳转规则（全站一致）**：
  - tab 之间用 `switchTab`；tab 页不能被 `navigateTo`（微信限制），所以从二级页回 tab 时用 `switchTab` 兜底。
  - 进入非 tab 页用 `navigateTo`；支付成功页用 `redirectTo` 替换收银台，防止返回栈重复下单。
  - 所有跳转都带 `fail` 兜底（toast 或 `switchTab` 回主页），不存在静默失败的跳转。
  - 全站 **0 处断链**（跳转目标均已在 `app.json` 注册，含分包前缀 `/pkg-extra/`）。

### 0.3 功能开关（个人主体裁剪）

`utils/features.js` 三个开关，决定入口显隐，代码与页面全部保留：

| 开关 | 当前值 | 关闭后行为 |
|---|---|---|
| `PAYMENT` | **false** | 隐藏「我的」页 VIP 横幅、会员页入口；权益视为全员可用；收银台/订单页仍注册但无入口可达 |
| `PHONE_LOGIN` | **false** | 隐藏登录页手机号入口、「我的」页绑手机号提示、设置页手机号项 |
| `COMMUNITY` | **true** | 社区保留上线。关闭时社区 tab 不渲染，相关入口（收藏菜谱、发帖）一并隐藏 |

> 资质就绪后把对应项置 `true` 即恢复，无需改页面代码。

### 0.4 登录态与身份

- 三种身份：**游客**（设备指纹哈希建号，默认昵称「家人」）、**微信登录**（`wx.login` + 后端 `code2session`）、**手机验证码**（当前开关关闭）。
- `app.js onLaunch` 只在**无 token** 时补游客会话——已有登录态不会被游客 token 覆盖（这是曾经的 P1 缺陷）。
- 受保护页面若拿到 401，`utils/api.js` 会自动补一次游客会话并重放请求（`skipReauth` 的白名单接口除外）。
- 角色：家庭内 `owner / admin / member`，决定**能否确认菜单**（见首页 `canConfirm`）；管理后台另有一套 `SUPER / MODERATOR / SUPPORT`。

### 0.5 页面态规范（全站统一）

每个数据页都必须具备四种态，这是验收项而非可选项：

| 态 | 组件/做法 | 要求 |
|---|---|---|
| 加载中 | `state-loading` 或骨架屏 | 首屏不允许白屏；首页另有看门狗超时兜底 |
| 空态 | `state-empty`（带图标/标题/描述/CTA） | 空态必须给出下一步动作（如「去菜谱库看看」），不能只有一句"暂无数据" |
| 失败态 | `state-empty` + 重试按钮 | **不允许把网络失败伪装成"没有数据"** |
| 离线兜底 | `wx.setStorageSync` 缓存 | 首页/菜单/购物清单缓存上次结果，弱网先渲染再刷新 |

## 2. tab 页详述

### 2.1 今日（`pages/home/index`）

**页面类型**：tab 页，长滚动页（`scroll-view` + 回顶悬浮键）。
**作用与场景**：全家一天里最常打开的页面。核心问题只有一个——**"今天吃什么"**：早上看早餐、中午前点午餐、下班前点晚餐。所有内容围绕"当前餐次"组织，不是一屏静态展示。

**结构分区（自上而下）**：

1. **Hero**：当前推荐菜的大图 + 标题 + 菜系/耗时；空态为文字驱动的紧凑版式。
2. **餐次选择器**：`早餐 / 午餐 / 晚餐` 三档 chips + 「本周 ›」跳周菜单。切换餐次后，下方菜单卡与许愿池**同步切到该餐次**。
3. **许愿池**（默认折叠一行，点开展开）：
   - 家人写"我想吃"（纯文本心愿，落 `family_wish`）；
   - 每条心愿显示：心愿文本、提出人、`待挑菜 ›`（未关联菜谱时）；
   - 底部主 CTA：「去挑菜 → 加入菜单」（有可确认权限时）/ 无权限显示「等做饭人确认」；
   - 心愿被挑中并加入菜单后**自动销愿**（详情页加菜链路带 `wishId`/`slot` 透传）。
4. **今日菜单暗卡**（首屏可见）：当前餐次已点的菜、状态（待做/烹饪中/已上桌）、点菜人；底部双按钮——「买菜」（ghost，进购物清单）与「开做 ›」（主按钮，进**厨房总控**，文案按状态变化：开做 N 道 / 继续做 / 已齐·回看）；空态分两种——"本餐次还没点菜但其他餐次有菜"与"全天都没成单"，文案不同。
5. **菜系 chips + 家里常做的菜**：按菜系横向筛选推荐，卡片可直达详情；末尾「查看全部」进菜谱库。
6. **右下角固定行动条**：显示待买项数，进购物清单。

**展示数据**：`DailyMenuView.items[]`（`mealType / status / addedByName / recipe`）、`RecipeCard`（含 `cookCount`、`lastCookedAt` 用于"常做"排序）、`family_wish` 列表、`ShoppingListView` 待买计数、当前用户家庭角色。

**跳转关系**：

| 方向 | 目标 | 触发 |
|---|---|---|
| 出 | `menu` | 今日菜单卡 / 查看全天 |
| 出 | `kitchen`（厨房总控） | 今日菜单卡「开做 ›」 |
| 出 | `weekly-menu` | 餐次栏「本周 ›」 |
| 出 | `recipes/search` | 心愿「待挑菜」（带 keyword + wishId + slot） |
| 出 | `recipe-detail` | 推荐菜卡 |
| 出 | `shopping` | 待买行动条 |
| 出 | `recipes`(switchTab) | 「查看全部」 |
| 入 | 任意 tab / 登录后 | `reLaunch` 到本页为首屏 |

**关键状态**：软失败（有缓存数据时刷新失败不摘下方结构，只给行内提示）、硬失败（无任何数据 → 整页 `state-empty` + 重试）。

### 2.2 菜谱（`pages/recipes/index`）

**页面类型**：tab 页，hero + 双列网格 + 上拉加载。
**作用与场景**：全家菜谱库的统一入口。用户带着"我想吃某类菜 / 看看家里有什么菜"的意图进来。

**结构分区**：Hero（优先展示**家里做过次数最多**的一道，无记录则列表首道）→ 来源 tab（全部 / 自建 / 社区 / 导入 / 我的收藏，后两项随 `COMMUNITY` 开关）→ 菜系筛选 chips → 忌口过滤开关（开启时按家庭成员忌口标签过滤，并显示"已过滤 N 道"）→ 双列菜谱卡网格 → 加载更多。

**展示数据**：`RecipeCard[]`——封面、标题、菜系、耗时、人份、评分、`cookCount`；忌口标签来自 `FamilyMemberItem.avoidTags`。

**跳转关系**：进 `recipe-detail`（卡片）、`recipe-edit`（新建）、`menu`（去点菜）、`shopping`（待买）；搜索入口跳 `recipes/search`。

**关键交互**：筛选状态组合生效（来源 × 菜系 × 忌口 × 关键词），本地过滤不重复请求；忌口过滤可一键关闭（"今天不按忌口筛"）。

---

### 2.3 社区（`pages/community/index`）

**页面类型**：tab 页，信息流。
**作用与场景**：邻里厨房——看别人家今天做什么，互相抄作业。也是 UGC 合规的主战场（发布走微信 `msgSecCheck` 机审 + 站内举报人工审核）。

**结构分区**：热门话题 chips（数据来自 `GET /api/community/topics`，取近帖标签频次 top 10，接口为空时回退内置话题；**点击在信息流内过滤**，出现「看全部 ×」解除条）→ 帖子流卡片（有配图显示首图 + 「N 图」角标）→ 发帖入口（浮层表单：标题/正文/标签/**配图最多 6 张**，走 `/api/upload` 通道）→ 帖子卡操作栏。

**帖子卡展示数据**：作者头像（文字+品牌色）、作者名、`likeCount` 赞 / `commentCount` 评论、标题、正文摘要、配图、关联菜谱卡（`recipe.title/cuisine/timeCost/servings`）、标签、操作栏（**点赞 / 收藏 / 评论 / 举报**）。

**关键交互**：
- 点赞：心形可点，本地乐观翻转 + 失败回滚，计数与后端 `like_count` 同步；
- 收藏：切换 `community_post_favorite`；
- 举报：弹层选原因（内容不实/步骤不全/疑似搬运/其他）+ 补充说明，落入人工审核队列；
- 帖子审核中（PENDING）只有作者本人可见。

**跳转关系**：出 → `pkg-extra/community/post-detail`（整卡点击）、`recipe-detail`（关联菜谱）、`recipes/search`（话题）。

---

### 2.4 冰箱（`pages/pantry/index`）

**页面类型**：tab 页。
**作用与场景**：把"家里有什么"记下来，反向回答"现在能做什么"。买菜回家顺手录入，做饭前扫一眼。

**结构分区**：库存总览（按蔬菜/肉类/调料/其他分类聚合，显示数量）→ 库存列表（名称、数量、到期状态：`未填到期日 / 已过期尽快处理 / 还剩 N 天 / 保质期还剩 N 天`）→ 「现在就能做」匹配区。

**匹配区数据**：`PantryMatchResult`——菜谱卡 + `matchedCount/totalCount`（显示 `4/6`）+ 匹配百分比进度条 + 缺料文案（`还差 排骨、淀粉` 或 `食材都有，直接开火`）。**判定全部用后端字段**，前端不再自行估算。

**关键交互**：库存增删改；点匹配卡进菜谱详情；过期项高亮提醒。

---

### 2.5 我的（`pages/me/index`）

**页面类型**：tab 页，聚合入口页。
**作用与场景**：个人与家庭的"总控台"——看记录、进工具、改设置。

**结构分区**：

| 区块 | 内容 |
|---|---|
| 家庭卡 | 家庭名、成员头像堆叠、`＋ 管理`（→ 成员列表） |
| VIP 横幅 | 受 `PAYMENT` 控制，关闭时不渲染 |
| 绑手机提示 | 受 `PHONE_LOGIN` 控制，且仅未绑定时提示 |
| 数据统计三条 | 菜谱数（→ 菜单）、做菜记录（→ 记录）、家庭成员（→ 成员） |
| 最近做菜记录 | 最近几条 `CookHistoryItem` + 「查看全部记录 ›」 |
| 厨房工具 | 周菜单、导入菜谱、我的收藏（受 `COMMUNITY`）、社区审核（仅 `isAdmin`） |
| 口味画像 | 本月菜系分布、常用口味标签、全家偏好（→ `preference-profile`） |
| 家庭管理 | 成员管理、邀请家人 |
| 设置组 | 资料编辑、消息通知、设置、意见反馈、关于、隐私政策、用户协议 |

**展示数据**：`AuthUser`（昵称/头像/`phoneBound`/`vip`/`admin`）、`FamilyProfile`、`CookHistoryItem[]`、口味统计。

**跳转关系**：见上表；管理入口仅在 `currentUser.admin` 为真时出现。

## 3. 二级页面详述

### 3.1 菜谱搜索（`pages/recipes/search/index`）

**类型**：二级页（自定义导航，sticky 搜索栏）。**场景**：从首页心愿、社区话题或菜谱页搜索框进来找具体某道菜。
**结构**：状态栏占位 + 返回 + 搜索框（可清除）+ 取消 → 结果标题（命中数 + 关键词高亮）→ 排序/筛选 chips（综合 / 最快 / 川菜 / 家常 / **做过的**）→ 双列网格。
**数据**：`RecipeCard[]`；「做过的」依据后端 `cookCount > 0`。
**键位语义**：关键词同时在**标题/菜系/标签/简介**里匹配；命中片段用 `.pop` 高亮分段渲染。
**跳转**：出 → `recipe-detail`（保留 `wishId`/`slot` 透传以完成销愿）；返回 → 上一页或 `home`。
**态**：加载中（`state-loading`）、失败（可重试，**不再伪装成"没有找到"**）、空（换关键词或清空）。

### 3.2 菜谱详情（`pages/recipe-detail/index`）

**类型**：二级页，核心转化页。**场景**：决策的最后一步——看清配料和做法，然后"加入菜单"或"开始做"。
**结构分区**：

1. Hero：封面、标题、菜系/耗时/难度、来源标签（自建/社区/导入/链接/文本）；
2. **食材**：`家里有 X/Y` 提示；每项标记**家里是否已有**（与冰箱库存比对）；
3. **做法**：有序步骤，支持图片、视频（`hoistVideo` 提升首屏）、小贴士；步骤图可全屏预览；
4. **家人评价**：昵称 + 星级 + 文字 + 时间，来自家庭成员的 `cook_history`（带备注的记录）；
5. 动作区：份量 stepper（±1 按比例换算用量）、加入今日菜单、缺的食材一键加购物清单、开始做菜、编辑、分享。

**展示数据**：`RecipeDetail`——`title/cuisine/tasteTags/timeCost/servings/difficulty/summary/steps[]/ingredients[]/coverImage/cookCount/reviews[]`。
**交互要点**：份量换算只对数值型用量生效（"适量/少许"原样保留）；已加入菜单则按钮进入"已在菜单里"状态（页面加载时并行查好，省一次往返）；来源为心愿链路时，加菜成功自动销愿并提示「愿望达成」。
**跳转**：出 → `cook-mode`（带 `servings`）、`recipe-edit`、`recipes`（返回兜底）。

### 3.3 菜谱编辑（`pages/recipe-edit/index`）

**类型**：二级页，三段式表单（介绍 / 用料 / 步骤），新建与编辑共用。
**场景**：把家里的拿手菜录进来；或修正已有菜谱。
**结构**：分段 tab → 介绍（封面、标题、菜系、耗时、人份、难度、口味标签、简介）→ 用料（名称/用量/单位，可增删行）→ 步骤（文本 + 配图 + 视频）→ 底部保存。
**数据**：写入 `CreateRecipeRequest` / `UpdateRecipeRequest`；菜系选项与全站 `constants.cuisineList` 同源（家常/川/粤/湘/鲁/西餐/日料）。
**态**：编辑模式先显示加载遮罩，避免空表单闪变后被数据覆盖；表单有完整性提示（食材数/步骤数/是否填简介）。
**来源**：从菜谱详情/菜谱页/导入页进入。

### 3.4 导入菜谱（`pages/import/index`）

**类型**：二级页。**场景**：在小红书/公众号看到菜谱，复制文案粘进来，一键结构化成菜谱。
**结构**：来源 tab（链接文案 / 手动输入）→ 粘贴框（字数统计、示例文案）→ 解析预览（可改标题/菜系/难度、换封面、替换步骤图）→ 保存为菜谱 → 「最近导入」列表。
**解析策略**：先本地解析（离线可用）；**解析不出食材或步骤时**才请求后端 `/api/import/preview` 兜底（此前远端解析是永远走不到的死路径）。
**态**：最近导入失败可点重试；图片上传失败有明确提示（不再静默）。
**已知边界**：拍照 OCR 识别未实现（入口已下线，重做需接 OCR 服务）。

### 3.5 菜单（`pages/menu/index`）

**厨房总控入口**：统计卡与快捷入口之间有「厨房总控」横幅（多道菜一起盯 · 计时/上桌都在这），跳 `pkg-extra/kitchen`。

**类型**：二级页（从首页/菜谱进入），核心"餐桌视图"。
**场景**：饭前确认今天吃什么、谁做、做到哪一步。
**结构分区**：Hero「今日餐桌」→ 分段（今日 / 本周）→ 统计卡 → **快捷三入口**（去做菜 / 看冰箱 / 看购物清单）→ 餐次分组（早餐/午餐/晚餐）→ 每道菜显示状态与操作 → **做菜顺序建议**（≥2 道待做时按耗时倒排，"先炖后炒同时上桌"）→ 底部固定行动条「一键生成购物清单」。
**数据**：`DailyMenuView`、`DailyMenuItemView.status`（`todo / cooking / done`）、`addedByName`。
**关键交互**：改状态（开做 → 烹饪中 → 已上桌）、删菜、跳购物清单前 400ms 定时导航（页面卸载会清理定时器）。

### 3.6 周菜单（`pages/weekly-menu/index`）

**类型**：二级页。**场景**：一次安排七天，买菜更省事。
**结构**：七天逐日安排卡片（每天午/晚两道）+ 一键生成/重排 + 点击某道进详情。
**数据**：后端 `EnhancedService` 按天生成的菜单计划。

### 3.7 购物清单（`pages/shopping/index`）

**类型**：二级页。**场景**：出门买菜前打开，边买边勾。
**结构**：进度概览（已买/总数 + 进度条 + `还差 N 项` / `今天买齐了` / `今天不用买`）→ 按品类分组（蔬菜/肉类/调料/其他）→ 未买区 + 已买区（可折叠）→ 手动添加食材。
**数据**：`ShoppingListView.items[]`——`ingredientName / amount / unit / purchased / sourceRecipes`。
**要点**：**来源标注**由后端回溯今日菜单得出——显示「来自 糖醋排骨」，手动添加的显示「手动补充」；封面取来源菜谱图。库存已有该食材时标「库存里已有」。

### 3.8 烹饪模式（`pages/cook-mode/index`）

**类型**：二级页，沉浸式暗底分步引导。**场景**：站在灶台前，手上是油，只能单手看。
**结构**：顶部进度点 + 计时按钮 → 当前步骤大图 + 大字号文本 + 步骤序号 → 上一步/下一步 → 食材勾选清单 → 步骤内嵌计时（从"约 N 分钟/N 秒"自动识别）→ 完成。
**交互要点**：屏幕常亮（进入开、离开关）；切后台停计时但按真实时间差续跑；从菜单"开做"进来会带 `menuItemId`，完成后自动把该菜标记为已上桌；详情页选好的人数会带进来**按比例缩放食材用量**；**食材清单可逐项点选勾账**（备齐一样勾一样，纯本地状态）；**步骤进度本地续做**——中途退出再进同一道菜自动回到上次步骤（`wx.storage` 存 `{i,total}`，厨房总控页读同一份显示"做到第几步"，完成时清除）；完成时弹真实评分（5/4/3 星或"先不评分"），不再写死 5 分。**步骤图/视频来自服务端 `recipe_step.image_url/video_url` 列**（2026-09-12 起结构化存储，旧 JSON-in-text hack 已删除）。
**跳转**：完成 → `cook-log`（带 `recipeId` 高亮刚做完的菜）。

### 3.9 做菜记录（`pages/cook-log/index`）

**类型**：二级页。**场景**：回看家里最近做了什么、谁做的、好不好吃；也是"再做一次"的入口。
**结构**：本月成就（做菜数 / 下厨天数 / 好评数）→ 本周打卡 7 态（`done / today / miss`）→ 掌勺人 chips 筛选 + 「五星」筛选 → 按月份分组的时间线（封面、日期+餐段、星级、掌勺人、备注）→ 折叠/展开。
**数据**：`CookHistoryItem[]`——`recipeTitle / cookedAt / score / remark / **cookedByName**`（家庭维度返回，按掌勺人筛选才有效）。
**交互**：卡片进详情；「再来一单」按当前时段（15 点前=午餐）把菜加回今日菜单；从烹饪模式跳来会高亮刚做完的那道。

## 4. 关键业务流（跨页链路）

### 4.1 主链路：点菜 → 做饭 → 买菜 → 记录

```
今日(home) ──点菜/挑菜──▶ 菜谱(recipes) 或 搜索(search) ──▶ 菜谱详情(recipe-detail)
                                                            │ 加入今日菜单
                                                            ▼
                                        今日菜单卡 ──▶ 菜单(menu) ──开做──▶ 烹饪模式(cook-mode)
                                                            │                    │ 完成（评分）
                                                            一键生成购物清单      ▼
                                                            ▼              做菜记录(cook-log)
                                                        购物清单(shopping)      │ 再来一单
                                                                              └──▶ 菜单(menu)
```

### 4.2 许愿链路（家人提需求 → 做饭人挑菜）

```
首页许愿池「＋我想吃」→ 写入 family_wish
   → 待挑菜（带 keyword + wishId + slot）→ 搜索页 → 菜谱详情 →「加入今日菜单」
   → 销愿（愿望达成提示）+ 心愿回到许愿池显示已关联
```

> 权限约束：普通 `member` 不能确认菜单，按钮显示「等做饭人确认」；`owner/admin` 可确认。

### 4.3 库存驱动链路

```
冰箱(pantry) 录入食材 →「现在就能做」匹配（后端算 matchedCount/totalCount）
   → 点卡进详情 → 缺料「加入购物清单」→ 购物清单(shopping) 勾选购买
```

### 4.4 内容链路（社区）

```
社区(community) 发帖 ──msgSecCheck 机审──▶ 通过：进信息流 / 待审：仅作者可见
   → 帖子详情(post-detail) 评论 / 点赞 / 收藏
   → 举报 → 后台人工审核队列（audit，管理员）
```

### 4.5 引导与登录链路

```
首次打开 ──无 token──▶ 自动游客会话（昵称「家人」）→ 今日(home)
   → 需要身份时（绑手机/会员/管理）──▶ 登录(auth/login)
   → 家庭：登录即建 1 人家庭；有邀请码 ──▶ family/join；想拉人 ──▶ family/invite
```

## 8. 点击交互规范（全站必须遵守）

> 本节是"点击行为"的验收标准。所有条目都在代码里有对应实现或自动检查，不是建议。

### 8.1 触控区域

| 规则 | 说明 |
|---|---|
| 可点元素高度 ≥ **88rpx**（约 44pt） | 手指与鼠标不同，低于此值点空率明显上升 |
| 小图标（关闭 ×、星标、返回）用热区扩展 | 加 `::after` 撑到 88rpx，**视觉尺寸不变**，避免为热区牺牲设计 |
| 相邻可点元素间距 ≥ 16rpx | 分段控件内部紧贴属设计意图，但每段自身高度已补到 88rpx |
| 已统一的实现 | `.chip`、分段 tab（菜单/购物/菜谱编辑）、社区操作栏、步进器 ±、返回键、收藏星标、提示条按钮 |

### 8.2 按下反馈（四态齐备）

| 状态 | 实现 | 用在哪 |
|---|---|---|
| 默认 | — | — |
| **按下** | `.tap-scale`（缩放 0.95） | 按钮、卡片、图标 |
| 按下（文字） | `.tap-dim`（压暗） | 纯文字链接（协议、隐私、切换） |
| 选中 | `.on` / `.active` | chip、分段、tab |
| 禁用 / 进行中 | `.is-busy`（半透明 + 阻断点击）、`disabled` 属性 | 提交类按钮 |

**约定**：只给最外层可点元素加反馈，容器与内部图标/文字不再单独加（否则多层同时缩放，视觉发抖）。

### 8.3 反馈时机

- 点击后 **100ms 内**必须有可见响应：能本地判断的就先改本地（乐观更新），不能的立刻 `wx.showLoading`。
- 预计超过 300ms 的操作（上传、生成周菜单、重建清单、支付、登录、保存）必须给 loading，且**期间不可重复点**。
- 结果必须回执：成功给 toast 或状态变化，失败给中文原因（`utils/api.js` 已统一错误文案），**不允许静默吞异常**。

### 8.4 防重复提交

统一走 `utils/interaction.js`：

```js
// 有 loading 与提示的常规写法
await runGuarded(this, `add-${id}`, () => api.addTodayMenuRecipe(id, slot), {
  loading: '加入中', success: '已加入今日菜单', fail: '加入失败，请重试'
});

// 乐观更新（点赞/勾选）自己控制 UI 时，只用防重
if (!guard(this, `like-${id}`)) return;
try { … } finally { release(this, `like-${id}`); }
```

**key 的粒度**：用动作 + 对象（`add-12`、`like-3`），这样"同时加不同的菜"允许并发，而"同一道菜连点"只发一次。

### 8.5 破坏性操作必须有二次确认

重建购物清单、重新排周菜单、撤菜、移除成员、删食材、退出登录、清除缓存、社区处置、下单支付 —— 全部走 `wx.showModal` 或 `state-dialog`，且确认文案要写清后果（例如"手动添加的条目将被覆盖"）。

### 8.6 导航行为

- tab 间 `switchTab`，非 tab 页 `navigateTo`；支付成功 `redirectTo` 替换收银台（防重复下单）。
- 点**当前** tab 不重复跳转（会重建页面栈，用户看到闪一下）；切换期间防抖；失败回退选中态。
- 所有跳转带 `fail` 兜底，不留"点了没反应"的路径。

### 8.7 回页刷新与状态一致性

- 首次进入给骨架屏；**回页刷新走静默模式**（`loadX(true)`），不整页闪骨架（已覆盖菜谱/社区/冰箱/菜单/购物清单/我的）。
- 写操作要等写入完成再跳转（如菜单"开做"先写状态再进烹饪模式），避免返回时读到旧状态。

### 8.8 自动化保障

| 检查 | 命令 | 拦住什么 |
|---|---|---|
| 事件必须有实现 | `node miniapp/test/static-check.js` | wxml 绑了 `bindtap="foo"` 但 js 没有 `foo` → "点了没反应"（已用反例验证有效） |
| 交互体检（报告制） | `node miniapp/test/interaction-audit.js` | 有事件无反馈、像按钮但无事件、声明尺寸 < 88rpx |

### 8.9 有意为之的例外（评审已确认，不算缺陷）

- 弹层/遮罩容器：`catchtap` 只为阻止冒泡或点击关闭，不加缩放。
- 加载遮罩、禁用占位按钮、输入区域：本身不产生点击反馈。
- `custom-tab-bar` 的 tab 项：反馈写在子元素上（整体缩放会与指示条动画打架）。
- 文本内联链接若天然很小但周围留白充足，按实际排版判断，不强制 88rpx。
