# Proposal: ui-click-display

## Why
提问人是小白，说「点击很乱、显示也一样」。上一轮已经修过撒谎文案和首页错误分层；现在还能踩到的是：点问候语进了菜详情、铃铛其实是买菜、菜单「点菜」被导航条挡住、按下会缩放但没去处、加载字还叠在旧列表上。先让手指落到的地方和眼睛看到的东西一致。

## What
- **点击说真话**：首页只拆问候语区的 `goDetail`，菜图/菜名/摘要仍进详情；铃铛改购物车形、放大镜改菜谱库形（`goShopping`/`goRecipes` 不改）；菜单「点菜」放进 nav-bar 右侧 slot；我的「本月做菜/家庭成员/最近上桌行」和社区话题去掉无 bindtap 的 `tap-scale`，话题芯片不再按按钮画 | refs: R-1 | verify: 点问候语不进详情，点菜名/图仍进；右上图标仍去买菜/菜谱且不再像铃铛/搜索；点「点菜」必进加菜；那四处不再像能点（无缩放、话题无按钮貌），不新接跳转
- **热区够大且不叠**：菜单「开始做/完成」高度 ≥80rpx；购物点食材名即可勾选，「移除」仍 `catchtap`；登录勾选整行可点且框 ≥64rpx；菜谱库 grid 的 + 不用 `float`（改已有 `corner` 或信息区旁） | refs: R-1 | verify: 菜单两钮不靠擦边才能点中；点「西红柿」能勾；登录点「我已阅读」文字也能勾，点协议仍进协议页；点菜名右下角进详情而不是加菜
- **加载/失败不和旧内容抢屏**：社区已有帖刷新不出「正在加载」、列表保留；无帖才出加载文案。冰箱失败清 `categories`，菜谱 catch 清 `displayedRecipes`（只出错误态）。`state-loading` 根节点加 `catchtouchmove` | refs: R-2 | verify: 再进社区看不见「正在加载」叠在旧帖上；冰箱/菜谱失败只有错误态、无旧列表可点；冰箱加载遮罩期间底下旧列表滑不动
- **社区话题标题只留一处**（去掉 `.tk` / `.th-title` 重复的那一个） | refs: R-2 | verify: 「热门话题」在页上只出现一次

**Not in this change**: 加高全站 360rpx Hero / 改 sheet 负边距；假热区新接跳转（本月做菜→记录、话题筛选）；首页铃铛改去消息、放大镜改去搜索页；换 UI 库 / token 立法 / 删死页；拷 zcode 密钥/海鸥人设；装 ios/android/CloudBase MCP；实施 `exp-closure-r3`。微信小程序 `weapp-dev` 已接到 Cursor（npm 包，不是旧本地文件）。

## How
- 零新依赖。菜单「点菜」用已有 nav-bar 右侧 slot，不在重叠处加 z-index。
- 首页只改图标几何，不改 `goShopping`/`goRecipes`。假热区只删 `tap-scale`/按钮貌，不绑新 tap。
- 失败只许清列表+错误态，禁止错误条盖在旧网格上。社区互斥只用于「有帖则不出加载文案」。冰箱 `state-loading` 锁滑动（遮罩下仍有旧列表）。
- `weapp-dev` 用 npm 包接到 Cursor，不复活已丢失的本地 `dist/index.js`。apply 前先归档另外三个 active change，否则 hook 拒绝。

## Risk
- 改图标后认不出右上角：购物车/书形必须一眼能懂；认不出就改回旧形。
- 购物整行可点误触「移除」：移除保持 `catchtap`，热区不扩到整行。
- 失败清列表会闪空：这是真话；若用户要「断网仍看旧菜」需推翻 DEC-1 显示项。
- 回滚：还原本 change 改过的前端文件即可。
