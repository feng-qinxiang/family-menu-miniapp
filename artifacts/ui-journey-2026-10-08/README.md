# 点菜小程序：四条主线的 UI 选型

本次交付三套可运行的设计预览，建议以 **A 现版优化** 为落地起点。三套方案使用同一份本地示例菜单，可以比较完整的“点菜 → 做菜 → 记录 → 社区”流程。

## 当前布局的问题

根据当前 Git 工作区代码复核：

- 底栏为“今日 / 菜谱 / 社区 / 冰箱 / 我的”，按内容与工具组织入口；做菜与记录没有同等级入口。见 `miniapp/app.json`。
- 首页以推荐菜的大图开场，餐次、家人心愿、已点菜单和开火操作依次展开。虽然菜单已经提前，但推荐区仍占据较多空间。见 `miniapp/pages/home/index.wxml`、`index.wxss`。
- 做菜记录的入口位于“我的”的统计与最近上桌区域。用户要找回自己的成品和心得，需要先进入个人页。见 `miniapp/pages/me/index.wxml`、`index.js`。
- 点菜、做菜、记录和社区的业务能力已经存在。设计重点是调整入口层级、页面主任务和连续操作，正式落地时应复用已有 API 与保存规则。

## 建议的信息架构

一级导航统一为 **点菜 / 做菜 / 记录 / 社区 / 我的**。

- **点菜**：餐次 → 家人想吃什么 → 已点菜单 → 去做菜；菜谱库和冰箱作为选菜工具。
- **做菜**：这一餐的菜 → 当前步骤 → 计时 → 上桌并记一笔；买菜入口跟随当前菜单。
- **记录**：成品、评分、备注与日期 → 再点一次或分享；优先展示最近一餐。
- **社区**：成品与经验 → 关联菜谱 → 我也点这道，回到自己的菜单。
- **我的**：家庭、资料与设置，承接低频管理。

## 三套方向

**A 现版优化（推荐）**：保留米白、番茄红和现有菜图，缩短推荐头图，突出已点菜单与“去做菜”。做菜保留菜图辅助辨认，记录与分享放在一起。延续当前视觉最容易，也便于逐页迁移。

**B 家庭点菜单**：暖纸色、菜单票据、家人参与和做菜日记；衬线标题、大步数、安静的排版。适合强调家庭共同点菜与一餐的记忆。正式落地前需重点验证长标题和长辈的阅读习惯。

**C 清爽厨房**：白绿配色、可折叠菜单、紧凑菜谱网格、周历和双列社区。适合每天快速选菜与开火。推荐保留其做菜页的信息层级；双列社区在大字模式下回到单列。

可组合：以 A 为基础，采用 B 的家人参与、C 的做菜排版。先确定布局，再微调颜色与字体。

## 如何查看

当前本地画廊：<http://127.0.0.1:8847/>。点击“点菜 / 做菜 / 记录 / 社区”可以并排比较三套模拟器截图，点击截图查看原图。

重新启动画廊，在 worktree 根目录执行：

```sh
python3 -m http.server 8847 --bind 127.0.0.1 --directory artifacts/ui-journey-2026-10-08
```

微信开发者工具打开此 worktree，编译入口：

```text
pkg-preview/journey/index
design=a
```

参数 `design` 可取 `a`、`b`、`c`；`view` 可取 `order`、`cook`、`record`、`community`、`me`；`chrome=0` 隐藏选型面板。页面顶部也可切换设计，底部切换主线；切换设计会保留当前示例操作。
