# 一家人的饭桌 · Figma 原型包

这是沿用已确认版本继续试改的设计原型，使用本地样例菜品与食材图片。包含 **17 个页面/状态、设计规范和流程画布**。

## 先直接看效果

打开 <http://127.0.0.1:8847/figma-prototype/?v=20261104-layout-focus#request>；也可以解压原型包，双击 `index.html`，离线查看。

`viewer.html` 是生成模板，直接打开时会自动转到完整的 `index.html`，并保留当前页面；若浏览器未自动跳转，点击“打开原型”。

- 点菜 → 冰箱能做 → 换一道 → 加入晚餐。
- 做菜 → 开始计时 → 下一步 → 完成并记录。
- 记录 → 晒到社区 → 作品详情 → 关联菜谱 → 再点一次。
- 冰箱中的食材图 → 拍照/相册/恢复文字选择界面。
- 买菜清单 → 临时加购的图片入口与“添加并继续”样例表单。
- 菜谱库 → 按需挑菜 → 输入要求 → 核对条件 → 挑一道或换一道。
- 冰箱 → 提醒设置 → 查看订阅说明或打开消息。

页面跳转、候选切换和两分钟计时可在网页里演示。点菜、采购、发布、上传和消息均为原型反馈，不写入真实家庭数据；搜索和分类目前展示入口，完整能力在现有小程序中。

本轮收紧菜谱库顶部：搜索与筛选合为一行，菜系/来源切换移入左栏，用料开关放进筛选；菜卡左侧大图、右侧关键信息，底栏核对冰箱并点菜。冰箱将临期食材、能做几道和挑菜集中显示，提醒默认折叠。帖子先看作品图，再连续阅读标题与心得。加购表单展示样例，点击图片与添加按钮只显示说明；真实拍照上传与连续保存需在小程序中体验。

“按需挑菜”可以真实输入并核对条件，复用小程序的有限本地规则，未接大模型。试试“两人吃，30分钟，不辣，冰箱有的”。支持人数、耗时、菜系、餐次、不辣、冰箱与临期等明确条件；未知或矛盾要求会提示修改，避免静默忽略。确认后从少量设计样例中挑菜，换一道仍遵守条件，无匹配时保留输入，关闭重开保留草稿。原型库存是样例，不能代表你家冰箱。

消息页新增标题旁的“全部标为已读”按钮，点击仅显示演示说明。正式小程序的耗时、人份筛选已经收成搜索下方两行；原型保留筛选入口并说明完整筛选需在小程序中体验。

最新四处反馈已同步：按需挑菜在输入后收起示例，逐行确认条件；冰箱摘要的名称与数量对齐；推荐卡固定左侧整图，所有说明集中右栏；详情缩短头图，用料左图右文、数量靠右，做法连续排列。无图食材仍显示名称，并保留拍照/选图入口。Figma 中的条件弹层展示填写后的静态状态，真实输入与换菜在网页演示。

## Figma 是什么

Figma 是用于设计界面与连接页面跳转的在线画布。它能改文字、图片、颜色和布局，也能把页面连成点击原型。它不会自动完成数据库、微信提醒或真实拍照上传。

不必为了查看这份原型先注册账号。以后需要多人一起改设计或更细地调整布局时再使用。

## 最容易的导入方法：SVG

1. 注册并登录 [Figma](https://www.figma.com/)，新建一个 Design 文件。
2. 解压 `family-menu-figma-kit.zip`。
3. 将 `screens` 中需要的 SVG 文件拖进画布。

SVG 保留矢量图形和内嵌图片，便于搬进画布。**Figma 的 SVG 导入可能将文字变成轮廓；它不会自动保留网页跳转、Auto Layout 或组件关系。** 如需原生可编辑文字与已连接的跳转，使用下面的开发插件。

## 原生文字与页面跳转：本地开发插件

1. 在 Figma 桌面版 Design 的插件菜单中找到 **Development / 开发 → New plugin / 创建插件**（部分版本在 Actions 搜索中），创建本地开发插件，取得 Figma 自动分配的插件 `id`。
2. 本包 `figma-plugin/manifest.json` 是开发模板，尚未包含账户分配的 `id`。将上一步的 `id` 加入模板，例如新增 `"id": "Figma 分配的插件 ID"`；保留原有 `main`、`documentAccess` 和 `networkAccess` 字段。
3. 从 **Development / 开发 → Import plugin from manifest / 从 manifest 导入插件**选择本包的 manifest。在空白 Design 文件中运行 **一家人的饭桌 · 可编辑原型**。
4. 插件新增一页，放入 17 个 390×844 页面/状态、2 张设计画布及页面跳转。从“点菜首页”启动 Present / 演示。

插件创建原生 Text 和 Rectangle 节点，图片为图像填充，图标为矢量；按原页面区块命名图层。会优先使用可用的中文字体，回退到 Inter。未自动转换为 Auto Layout 或可复用 Figma Component，避免宣称不存在的组件能力。动态条件输入、计时和筛选属于网页演示，Figma 中连接的是静态页面跳转。

每次运行新增一页，不删除或覆盖已有页面。插件不请求网络权限、不使用 Token、也不上传本地源码或业务数据。它只携带此包的设计样例与图片。

**当前验证边界：**已检查 SVG、画布范围、跳转目标和插件的本地生成逻辑，并验收浏览器原型；本环境没有登录的 Figma 或 Figma 写入连接器，尚未在真实 Figma 文件中运行该插件。实际字体回退与 Figma 导入效果需在导入后检查。

小程序源码已同步本轮试改，但微信开发者工具返回 `APPID_ERROR`，当前账号缺少该 AppID 的开发者权限；本轮未完成原生编译或模拟器验收。网页图不作为本轮原生运行证据。

## 文件与复跑

- `screens/*.svg`：17 个页面/状态及 2 张画布。
- `index.html`：完整离线点击原型。
- `prototype-data.json`：原生图层、颜色、图片与跳转数据。
- `figma-plugin/`：离线开发插件。
- `build-checks.json`、`importer-checks.json`、`browser-checks.json`：验证记录；本轮交互与响应式补验在上级目录 `layout-focus-browser-checks.json`、`layout-focus-responsive-checks.json`，`verify.cjs` 是可运行的本地导入逻辑检查。
- worktree 中的 `build.py`、`viewer.html`、`plugin-template.js`：生成源文件，复跑时使用项目已有的图片与图标。

在 worktree 中复跑：

```sh
python3 artifacts/ui-journey-2026-10-08/figma-prototype/build.py
/Users/xx/.local/opt/node22/bin/node artifacts/ui-journey-2026-10-08/figma-prototype/verify.cjs
```
